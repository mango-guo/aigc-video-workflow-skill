# 提示词与「少随机抽卡」模式

> 来源：v2 的提示词模块库（主体 ID / 场景 / 风格 / 避免）与阶段 5 的 3 轮重试规则，加上 X 社区的重复做法（`research-notes-x.md` §1–§3、§7）。**工具名与具体限制都会变**，见 `tools.md`；本文件只写不依赖具体模型的做法。

## 1. 模块化提示词

沿用 v2：每个镜头提示词 = **主体 ID 块 + 场景块 + 动作与镜头块 + 风格块 + 避免块**。主体 ID、风格块来自阶段 2 资产（v1.0 锁定）；**镜头间只改动作和镜头块**。

```text
[主体ID]  引用资产库：角色A_v1.0 / 产品_v1.0（外观描述不再改写）
[场景]    地点 / 时间 / 光线 / 环境动态
[动作+镜头] 景别、机位、运镜、主体动作、起止状态、时长
[风格]    引用视觉圣经风格块
[避免]    不要网格 / 边框 / 编号 / 字幕 / Logo 变形 / 多余人物
```

## 2. 图生视频：做减法

首帧已经定义了主体、构图、光线、风格，提示词**只写运动、镜头运动和时间推进**，不要再长篇描述外貌与背景（与 v2 一致；社区里也有「图像负责审美，视频只负责物理动态，提示词做减法」的说法，https://x.com/aiyyozhoushuai/status/2099013698551742813 ，个人观点）。

## 3. 首尾帧与多关键帧

- **首帧 + 尾帧**：把镜头起止状态定死，让模型填充中间。适用转场、变身、从 A 走到 B（https://x.com/romance0x/status/2107146395824070877 ；https://x.com/jagerchief/status/2109514523635785894 ）。
- **首帧 = 尾帧**：无缝循环背景（https://x.com/cartersurach/status/2095942589711020233 ）。
- **多关键帧**：部分新工具允许一个长镜头里放多个关键帧，每个是镜头必须到达的节拍（https://x.com/ichelpark/status/2111549585479049585 ，工具规格见 `tools.md`，需核对）。
- **多段连续**：把一场的 4–9 个关键帧分别当首帧，逐镜动画化，再在剪辑里接起来（https://x.com/ppouladzadeh/status/2103881039643033983 ，6 关键帧 → 5 镜头）。
- 首尾帧 vs 参考模式 谁更稳，社区无定论：**列为 A 类镜头的测试变量**（阶段 4）。

## 4. 参考图锚定（Reference Lock）

- 每张参考图标注「这张锁定什么」：首帧 / 身份 / 服装 / 产品 / 场景；身份块里写 never changes（https://x.com/abxxai/status/2114723977394585617 ，结构参考）。
- 产品参考板的写法：以上传图为产品外观、包装、Logo、字体、比例、颜色的唯一依据（https://x.com/meAsifAi/status/2103789176831303808 ，示例品牌虚构）。
- 角色用四视图 / 转面设定表锁脸；设定表仍可能有风格与气质漂移，需要抽查（https://x.com/yhslgg/status/2114602845865726091 ；https://x.com/smoermeow/status/2096178435454374334 ）。
- 先出一张首帧，再把它作为参考用于其余镜头（https://x.com/PixelDojoAI/status/2113384513883828350 ）。

## 5. 时间码式多镜头写法

当工具支持一次生成多个镜头 / 较长镜头时，**把提示词写成带时间码的 shot list，而不是一段散文**，让模型不必猜时间（https://x.com/ziroel_98/status/2114601859726082489 ）：

```text
总体描述：（一句话：人物、地点、基调、风格块）
Shot 1 (0–4s): [景别], [运镜]. [动作]. Cut as [触发条件].
Shot 2 (4–9s): [景别], [运镜]. [动作]. Cut as [触发条件].
Shot 3 (9–12s): ...
音频：（对白 / 音乐 / 音效，见阶段 1 声音骨架）
避免：（本镜头专属）
```

要点：每镜头一个主动作；切点写触发条件；不超过工具支持的镜头数；不要在一个提示词里混几个不同场地。

## 6. 短镜头 + 多抽卡

- 默认**一个镜头一个动作，2–5 秒**；A 类镜头多抽几次，B / C 类少抽或用图 + 轻运动。
- **生成时长 ≥ 镜头时长 × 1.3–2**（v3 把 v2 的「头尾各 0.5–1 秒」扩展为「多留余量」，社区做法见 beegnyc：先生成带余量的覆盖，再裁成多个镜头，https://x.com/beegnyc/status/2106165724964065785 ）【建议值·需按项目实测】。
- 3 轮规则：同一镜头最多 3 轮重试，**每轮只改一个变量**（提示词 / 参考图 / 模型 / 种子 / 时长）。3 轮仍不过，回退到更早阶段（常见是关键帧或镜头设计问题，而不是「再抽一次」）。
- 抽卡记录写入提示词包：镜头号、版本号、改了哪一个变量、结果。

## 7. 重生成时「改什么 + 保留什么」

对单镜头重做的指令里，**明确写要变的，也明确写要保留的**（人物、构图、节奏点、配乐卡点等），避免模型把已通过的部分一并改掉（https://x.com/beegnyc/status/2106165724964065785 的第 7 步）。

## 8. 一致性检查（每镜头）

- 同一角色：脸、发型、服装、体型；同一产品：形状、颜色、Logo（品牌项目走 `brand-consistency-checklist.md`）
- 同一场景：光线方向、色温、时间
- 镜头轴线、视线方向、动作衔接
- 画面文字与 Logo 不由模型生成，后期叠加

## 9. 常见失败与对策（沿用 v2 问题标签）

| 现象 | 常见根因 | 对策（一次只改一个） |
| --- | --- | --- |
| 人物 / 产品跨镜头漂移 | 参考不足或提示词重写外观 | 加参考板 / 复用 v1.0 外观块 |
| 动作不对 | 一镜多动作 / 描述含糊 | 拆镜头；写起止状态 |
| 画面太「抛光」 | 参考图过度精致 | 换更生活化的参考（UGC，见 `ugc-playbook.md`） |
| 文字乱码 | 让模型生成文字 | 后期叠加 |
| 节奏拖 | 镜头过长 | 缩短；用 animatic 先排节奏 |
| 声音假 | 原生声音 | 外部配音 + 音频参考（阶段 4 对比） |

> 对策是起点而不是定论。每次采用都记录结果，进入复盘。
